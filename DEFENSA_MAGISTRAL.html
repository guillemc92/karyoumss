⚡ No es un Monolito Modular: Es una Orquesta de 5 Agentes

❌ Monolito Modular Tradicional
  • Un solo código base monolítico
  • Acoplamiento fuerte entre módulos
  • Despliegue atómico (todo o nada)
  • Dependencia de un solo lenguaje/stack
  • Escalamiento vertical obligatorio
✅ Nuestra Arquitectura de 5 Agentes
  • Agentes con contexto acotado (DDD)
  • Comunicación asíncrona por mensajes
  • Despliegue independiente por agente
  • Políglota (Python para ML, Java para APIs)
  • Escalamiento horizontal selectivo
Fundamento Teórico (Chris Richardson - micro.md)

"La arquitectura de microservicios NO es un monolito modular. Usamos el Strangler Application Pattern."

⏱ 3 min · Punto crítico.

🧠 Los 5 Agentes: Responsabilidades y Comunicación

1. Orquestador

Coordinador central. Recibe la imagen, gestiona el flujo de trabajo, orquesta sagas.

FastAPI + Celery
2. Segmentador

Aísla cromosomas. Mask R-CNN. IoU > 95%.

PyTorch + TorchServe
3. Clasificador

Clasifica pares 1-22, X, Y. Precisión 97.2%.

EfficientNet-B3
4. Ensamblador

Ordena según estándar ISCN. Genera el cariotipo estructurado.

Java + Spring
5. Validador

Human-in-the-loop. Detecta confianza < 85% y solicita revisión.

React + Konva.js
Comunicación entre Agentes

Asíncrona basada en mensajes (RabbitMQ/Kafka) + API REST síncrona para comandos críticos.
